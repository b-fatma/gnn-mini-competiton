### Reminder: GNN Layer Operations (Building Blocks)

A GNN layer is composed of modular building blocks (carried forward from Lecture 3):

| Operation | Purpose |
|---|---|
| **AGG** | Integrate information from self & neighbors — the GNN hallmark |
| **Transform** | Represent embeddings better — classical in ML |
| **MSG Passing** | Mixed actions of AGG + Transform: `H_{k+1} = f(H_k, A)` |
| **Nonlinearity** | Capture complexity & identify important patterns |
| **BN** (Batch Norm) | Stabilize optimization & control embedding variance between layers |
| **Dropout** | Drop nodes to regularize & increase expressiveness |
| **Prediction Head** | Define the target learning task & its parameters |

---

### Reminder: Three Training Strategies

| Strategy | Update Rule | Key Properties |
|---|---|---|
| **Stochastic GD** | Per data point: `w_{t+1} = w_t − η∇L_{point}` | Frequent, noisy updates; high variance; computationally inefficient for large datasets |
| **Batch GD** | Whole dataset: `w_{t+1} = w_t − η∇L_{dataset}` | Stable gradients; updated once per epoch; very memory-intensive; risk of overfitting |
| **Mini-Batch GD** | Per batch: `w_{t+1} = w_t − η∇L_{batch}` | Balanced convergence; GPU-parallelizable; acts as regularizer via batch variability |

**Mini-Batch GD** is generally preferred for GNN training because it:
- Strikes a balance between stability and speed
- Is feasible for large datasets (reduced memory requirement)
- Introduces noise as implicit regularization → better generalization
- The mini-batch size is a tunable **hyperparameter**

---

### How to Define Batches for GNN Training?

**Core challenge:** Each node in a batch `B` depends on its neighbors in the previous layer, which in turn depend on **their** neighbors in the layer before — equivalent to the node's **receptive field**.

To compute the loss at a single node at layer `k`:
- Requires neighbor node embeddings at layer `k-1`
- Which recursively requires their neighbors at layer `k-2`, and so on down

> **Mini-batch SGD** uses the subgraph that forms the **union of the k-hop neighbors** of all nodes in batch `B`. Remaining graph nodes do not contribute to the node update.

---

### Node Sampling (GraphSAGE — Hamilton et al., 2017)

**Approach:** Randomly select a subset of target nodes and work **backwards** through the network, adding a subset of nodes in the receptive field at each stage.

**Steps:**
1. Randomly define **mini-batches** of nodes
2. Randomly sample a **fixed number** of their neighbors in the previous layer
3. Then randomly sample a fixed number of **their** neighbors in the layer before, and so on

**Key question:** Will the node subgraph increase in size with each layer?
→ **Yes**, but in a **much more controlled** way than full neighborhood expansion.

**Key question:** If the same batch is drawn twice, will we get the same updated embedding for node `v`?
→ **No** — contributing neighbors are selected randomly. Even with the same batch, different neighbors are sampled → different embeddings. This **randomness acts as a regularizer**.

**Pros:**
- Reduces computational cost (trains on subset of nodes)
- More efficient memory usage for large graphs

**Cons:**
- **Redundant computations**: if two nodes share the same neighbor, that neighbor's embedding must be computed twice (recursive redundancy)

---

### The Graph Expansion Problem

**What happens when the graph is dense and the GNN is deep?**

⚠️ **Graph expansion problem:** Every node may be in the receptive field of every output node → memory usage and compute budget **explode**.

⚠️ Costly to train and sometimes **impossible** (exponential time complexity relative to GCN depth)!

---

### Subgraph Sampling & Graph Partitioning

Two smarter batching strategies to address the graph expansion problem:

**Subgraph Sampling:**
1. Randomly draw subgraphs or divide the original graph into subgraphs
2. Train on these as **independent data samples**
- Examples: GraphSAINT (Zeng et al., 2019), ClusterGCN (Chiang et al., 2019)

**Graph Partitioning (ClusterGCN):**
1. **Cluster** graph nodes into disjoint subsets using a clustering algorithm, maximizing **within-cluster links**
2. Treat each cluster as a batch, or randomly combine clusters into a batch by reinstating inter-cluster links from the original graph

Each cluster defines a batch of training nodes with dense intra-batch connectivity.

## Page 2 — Sampling Methods Recap & Batch Normalization

### Recap: Three GNN Sampling Strategies

#### 1. Node Sampling
- Randomly select target nodes, work back through receptive field at each layer
- **Examples:** GraphSAGE, VRGCN, PinSAGE
- ✅ Computationally efficient; memory efficient
- ❌ Redundant embedding computations (shared neighbors computed multiple times)

#### 2. Layer Sampling
- **Idea:** Sample nodes in **each layer independently**, addressing the node count explosion in node sampling
- **FastGCN (Chen et al., 2018):**
  1. Calculate sampling probability based on **node degree**; sample a fixed number per layer
  2. Use only sampled nodes to build a smaller **sampled adjacency matrix** → reduced compute
  - Note: sampled nodes from two consecutive layers are **not necessarily connected**
- **LADIES (Zou et al., 2019) — Layer-Dependent Importance Sampling:**
  1. For each current layer `k`, based on nodes sampled in upper layer `k+1`, collect all their neighbors and build a **bipartite graph** between the two layers
  2. Calculate sampling probability by **node degree** in current layer to reduce sampling variance
  3. Sample a fixed number of nodes based on this probability
- **Examples:** FastGCN, adaptive sampling (Huang et al., 2018), LADIES, L²-GCN
- ✅ Avoids redundant computation; more memory efficient
- ❌ May disrupt links between neighboring nodes across consecutive layers → isolated nodes, sparsified graph

#### 3. Subgraph Sampling
- Randomly draw subgraphs or partition the graph; train on each as an independent sample
- **Examples:** GraphSAINT, ClusterGCN
- ✅ Dramatically reduces data size per iteration; scales to very large graphs
- ❌ Designing effective subgraph sampling strategies can be complex and computationally costly

**Shared limitations across all sampling strategies:**
1. **Information Loss:** Model trained on subsets may miss global structure
2. **Sampling Bias:** Certain graph regions may be consistently under-sampled
3. **Limited Global Information:** Sampling can restrict the model's ability to capture global graph properties

### Batch Normalization (BN)

**Aim:** Stabilize GNN training by normalizing node embeddings within each batch.

**Mechanism — two steps:**

**Step 1 — Compute mean and variance** over `|B|` embeddings in batch `B`:
```
m_B = (1/|B|) Σ_{i∈B} h_i          (empirical mean)
s_B = √( (1/|B|) Σ_{i∈B} (h_i − m_B)² )   (empirical standard deviation)
```

**Step 2 — Normalize node embeddings** using computed statistics:
```
ĥ_i = γ · (h_i − m_B) / s_B + β     ∀i ∈ B
```
- `γ` and `β` are **learnable** scale and shift parameters (BatchNorm shifts and rescales each activation so its mean and variance across the batch become values learned during training)

#### Benefits of Batch Normalization

**Higher learning rates:** BN makes the loss surface and its gradient change more **smoothly** (reduces shattered gradients) → the surface is more predictable → higher learning rates can be used safely.

**Regularization:** BN injects **noise** into training because normalization depends on batch statistics. Each training sample's activations are normalized by an amount that depends on the other batch members → processed slightly differently per batch → acts as implicit regularizer → models generalize better.

**Stable forward propagation:** BN controls the **variance of learned embeddings between consecutive layers**, stabilizing the network's transformation functions between neighboring layers → the network can easily control its effective learning path.

> Without BN, embeddings `h_{k-1}` and `h_k` can have very different distributions (covariate shift). With BN, the distributions are stabilized → **stable covariate shift**.

## Page 3 — Dropout & GNN Expressive Power

### A Single GNN Layer — Full Structure

A complete GNN layer can take the following form (top to bottom):

```
① Linear (Transform)
② BN (Batch Normalization)
③ Dropout
④ Activation (Nonlinearity)
⑤ Attention
⑥ Aggregation
```

- One can include different deep learning modules depending on the downstream task
- **Example:** add MLP layers **before** and/or **after** a GNN layer for additional representational power
- The design of a general GNN layer remains an **active area of research**

---

### Conventional Dropout

**Aim:** Regularize a neural network to avoid overfitting.

**During training:** Randomly set neurons to **zero** (drop out) with probability `p` in a particular layer.

**During testing:** Use **all neurons** for computation.

**Effect:** Reduces the effective number of neurons → forces the network to learn redundant representations → acts as regularization.

---

### Dropout for GNNs

In GNNs, dropout follows up the **BN layer**. In the absence of a BN layer, dropout is applied directly to the **linear layer** in the message function.

**Effect:** Randomly drops training **nodes** (rather than individual neurons), creating different subgraph views per forward pass.

---

### DropGNN (Papp et al., NeurIPS 2021)

> **Key insight:** Dropout ≠ Sampling in GNNs

**Paper:** "DropGNN: Random Dropouts Increase the Expressiveness of Graph Neural Networks"

**Core idea:** In each run, remove ("drop out") each node in the graph with a small probability `p`. This allows the network to **observe various slightly perturbed versions** of the node's d-hop neighborhood — rather than just the actual extended neighborhood.

**Key difference from conventional dropout:**
- Conventional dropout: applied during training only; at test time all neurons are used
- **DropGNN: drops nodes during both training AND testing**, since the goal is to observe a **similar distribution of dropout patterns** during both phases

**Why this helps expressiveness:** Different runs produce different subgraph views → the model can effectively observe the **actual extended neighborhood** from multiple angles → O(γ) different runs is sufficient to observe a reasonable distribution of dropouts in a neighborhood of size γ.

**Results:**
- DropGNNs clearly **outperform** standard GNNs on problems that are unsolvable for standard GNNs
- Competitive performance on established graph benchmarks
- Particularly impressive when graph structure is a crucial factor

**Illustration:** 4 possible dropout combinations from an example 2-hop neighborhood: a 0-dropout, two different 1-dropouts, and a 2-dropout.

## Page 4 — Inductive vs. Transductive GNN Training

### The Two Learning Paradigms

| Property | Inductive Learning | Transductive Learning |
|---|---|---|
| **Rule learning** | ✅ Learns a rule that maps graph → output, applied to new data | ❌ Produces only a labeling for unknown outputs — no generalizable rule |
| **Test data access** | ❌ Cannot access original features of testing samples during training | ✅ Considers both labeled and unlabeled data simultaneously |
| **Unlabeled data** | ❌ No access | ✅ Can use patterns in unlabeled data to improve decisions |
| **Memory** | ✅ No need to store testing nodes and their features in memory | ❌ High memory cost — jointly stores training and testing node information |
| **Computational time** | ✅ Lower | ❌ Higher |
| **Unseen nodes** | ✅ Can test on truly unseen (new) nodes | ❌ When new unlabeled data arrives, model must be **retrained from scratch** |

> **Inductive:** train on training graphs, test on a separate test graph (generalize)
> **Transductive:** train & test jointly on the **same** graph — some nodes labeled, some unknown

---

### Inductive Node Classification

**Setting:** Given a set of training graphs with known node labels, learn a model and apply it to a **new test graph**.

**Prediction function (graph-level):**
```
y^test = sig[ β_K + ω_K H_K 1/N ]
```
Where:
- `H_K ∈ ℝ^{N×d_K}` = final-layer node embeddings of the test graph
- `ω_K` = learned weights
- `1/N` = averaging vector (mean pooling across N nodes)
- `sig(·)` applies sigmoid **independently** to every element of the row vector input

The model is applied directly to the test graph's structure and features after training — no retraining needed.

---

### Transductive Node Classification

**Setting:** There is **one large graph** where some nodes have labels (training nodes) and others are unknown (test nodes). Training and evaluation happen on the **same graph**.

**Prediction function:**
```
ỹ = sig[ β_K 1ᵀ + ω_K H_K ]
y ∈ ℝⁿ
```
Where `N` = number of test nodes in the graph `G`.

- The sigmoid `sig(·)` applies **independently** to every element of the row vector input
- The model optimizes over **all nodes** simultaneously, leveraging unlabeled test node structure during training
- After training, predictions are directly read off for the unknown nodes

**Key advantage:** Transductive learning can exploit the **topology and features of unlabeled test nodes** during training, which can be beneficial when the test graph structure carries meaningful information.

**Key disadvantage:** Cannot generalize — when new test nodes arrive, the whole model must be **retrained from scratch**.

---

### Question for Reflection

> **How to batch nodes in a transductive learning paradigm?**

In transductive learning, all nodes (labeled and unlabeled) are present in the same graph. Batching must therefore handle the fact that unlabeled test nodes are visible but their labels are masked during training — the batch structure needs to preserve connectivity across both labeled and unlabeled nodes.

## Key Takeaways

1. **Three gradient descent strategies** trade off memory, stability, and compute: SGD (noisy but frequent), Batch GD (stable but memory-heavy), and Mini-Batch GD (the practical sweet spot for GNN training).

2. **GNN batching** is non-trivial because of receptive field expansion — each node's loss computation requires the embeddings of its multi-hop neighbors. Mini-batch SGD uses the union of k-hop neighbor subgraphs.

3. **Three sampling strategies** address the graph expansion problem: node sampling (GraphSAGE — random backward neighbor selection), layer sampling (FastGCN, LADIES — independent per-layer sampling by degree), and subgraph sampling (ClusterGCN — cluster-based partitioning with dense intra-batch edges).

4. **Batch Normalization** stabilizes GNN training by normalizing embeddings to zero mean and unit variance within each batch, allowing higher learning rates, injecting implicit regularization noise, and preventing covariate shift between layers.

5. **Dropout in GNNs** follows BN and drops nodes (not just neurons) randomly during training. **DropGNN** extends this to test time, using multiple stochastic views of a node's neighborhood to directly increase GNN expressiveness — not just regularization.

6. **Inductive learning** generalizes to new graphs and unseen nodes without retraining — the model learns a transferable mapping rule. **Transductive learning** operates on a single graph with partially labeled nodes, leveraging unlabeled test node topology during training but requiring full retraining when new data arrives.
