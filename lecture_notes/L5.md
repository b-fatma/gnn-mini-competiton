## Page 1 — Node Permutation Invariance & Equivariance

### Reminder: Transformation Invariance in Euclidean Deep Learning

**Invariance** means the output of a function `f[x]` is the **same** regardless of the transformation `t[x]` applied to the input:
```
f[t[x]] = f[x]
```
- Example: image classification networks should be **invariant** to geometric transformations (translation, rotation, flipping, warping) — the object is still identified as the same regardless of its orientation.

**Equivariance** means the output changes **in the same way** as the input under a transformation:
```
f[t[x]] = t[f[x]]
```
- Example: per-pixel image segmentation networks should be **equivariant** — if the image is rotated, the segmentation map should be rotated in the same way.

---

### Which Type of Invariance Do GNNs Need?

**The core problem:** A graph with `n` nodes has `n!` potential adjacency matrices representing the same topology (one for each possible ordering of the nodes). If a GNN is **node order-variant**, permuting the node indices would produce different predicted outputs for the **same graph** — which is incorrect.

> **GNNs need to be permutation-invariant**, learning representations (embeddings) that do **not** depend on the indexing of graph nodes.

---

### Node Permutation Invariance in GNNs

**Formal definition:** Let `f` denote the mapping function of a GNN onto the final `d`-dimensional embedding space:
```
f: G → ℝᵈ
G ↦ f(A, X)
```

Let `i` and `j` denote different node orderings of the same graph. `f` is **permutation-invariant** if:
```
f(A_i, X_i) = f(A_j, X_j)     (same output regardless of ordering)
```

**Formalization for each GCN layer:** A graph function `f_k` is permutation-invariant if for each GCN layer `k`, for any permutation matrix `P`:
```
f: ℝⁿˣⁿ × ℝᵈₖˣⁿ → ℝⁿˣᵈₖ₊₁
h_{k+1} = f(A, H_k) = f(PᵀAP, H_k P)
```
→ The **learned graph embedding is invariant to node permutation**.

**Permutation matrix `P` mechanics:**
- Permuting node indices in the adjacency matrix requires **both** permuting rows AND columns: `PᵀAP`
- Don't forget to also permute the embedding matrix `H_k`!
- `P(i, π(i)) = 1` — each row and column has exactly one entry of 1

**True or False — Properties of Permutations:**
- ✅ Permutations `π` are **bijections** from a set to itself
- ✅ Permutation is **associative**: `π ∘ (σ ∘ δ) = (π ∘ σ) ∘ δ`
- ❌ Permutation is **NOT commutative**: `π ∘ σ ≠ σ ∘ π` (in general)

**Key insight — Computational Graphs:**
- The structure of a node's **computational graph** does NOT depend on its index (color)
- Permuting node colors produces the **same** computational graph structure → GCN is permutation invariant ✅
- This is in contrast to **images** (permuting pixels creates a different image) and **text** (permuting words creates a different sentence) — permutation invariance does NOT apply there

---

### Node Permutation Equivariance in GNNs

Considering **all nodes** in a graph, GCN computation is **permutation equivariant**: if we permute the node indices, the node embeddings at each stage are permuted in the **same way**.

Formally, if `P` is a permutation matrix, then at every layer:
```
H_{k+1} · P = F[H_k, P^T A P, φ_k]
```
(outputs the new embedding permuted in the same way — *msg update rule*)

**Task-dependent behavior:**
- **Node classification & edge prediction tasks** → output should be **equivariant** to permutations of node indices
- **Graph-level tasks** → the final layer aggregates across the entire graph, so the output is **invariant** to node order:
```
y = sig[ β_K + ω_K (H_K 1) / N ]
  = sig[ β_K + ω_K (H_K P · P^T 1) / N ]     (invariant since P^T 1 = 1)
```

> ✅ For graphs, it is possible to define networks that ensure **equivariance OR invariance** to permutations.

---

### Problem Solving Example

**Problem:** Consider a simple GNN layer:
```
H_{k+1} = GraphLayer[H_k, A]
         = a[ β_k 1ᵀ + Ω_k H_k + Ω_k H_k A ]
```
Where `H` is a `D×N` matrix (N node embeddings as columns), `A` is the `N×N` adjacency matrix, `β` is bias, `Ω` is the weight matrix, and `[H_k; H_kA]` denotes vertical concatenation.

**Show:** `GraphLayer[H_k, A]P = GraphLayer[H_k P, PᵀAP]`

**Proof:**
```
GraphLayer[H_k, PᵀAP] = a[ β_k 1ᵀ + Ω_k H_k P + Ω_k H_k P · PᵀAP ]
                       = a[ β_k 1ᵀ + Ω_k H_k P + Ω_k H_k AP ]
                       = a[ β_k 1ᵀ + Ω_k H_k + Ω_k H_k A ] · P
                       = GraphLayer[H_k, A] · P  ✅
```
→ The GNN layer is permutation equivariant.

## Page 2 — Expressive Power of GNNs

### K-Hop Similarity in Node Local Structure

The **degree** of a node captures its 1-hop neighborhood. But two nodes can have the same degree yet live in completely different local structures. As we go deeper (k=1, k=2 layers), the GNN captures increasingly larger neighborhoods.

Example observations from the lecture:
- At `k=1`: nodes may have the same degree `d(●) = d(○)` but different 2-hop neighborhoods
- At `k=2`: we can distinguish more complex structural differences by examining the full 2-hop subtree

---

### Expressive Power of a GNN Model

**Definition:** An **expressive GNN** maximizes its node representation capacity in the embedding space by mapping **different local neighborhoods to different embeddings** — especially when nodes have similar embeddings.

Mathematically:
- A **highly expressive GNN** maps local neighborhoods to node embeddings **injectively** (one-to-one)
- It uses an **injective neighbor aggregation** at each layer `k`
- Since neighborhood aggregation is modeled through the **node computational graph**, an expressive GNN maps nodes with **different computation graphs to different embeddings**

**Key property:**
```
If C(n) ≠ C(m)  →  h_{k+1}^(n) ≠ h_{k+1}^(m)
```
*(where C(n) denotes the computational graph of node n)*

This relies on the update rule:
```
h_{k+1}^(n) = a[ β_k + Ω_k h_k^(n) + Ω_k · agg[n,k] ]
```

---

### Rooted Subtree Structures & Computational Graphs

Computational graphs are identical to **rooted subtree structures** around each node, defined by **recursively unfolding neighboring nodes from the root node**.

**Case a — Same structure AND same original embeddings:**
- GNN generates the **same** embedding for root nodes → cannot distinguish them
- This is a **failure case** of GNNs

**Case b — Same structure but different original embeddings:**
- GNN may generate **different** embeddings → can distinguish

**Failure case:** When two different graph structures produce the **same** computational graph (e.g., symmetric neighborhood structures), GNNs fail to distinguish the nodes even if the graphs are non-isomorphic.

---

### Rooted Subtree Isomorphism Test

**Can GNN node embeddings distinguish different neighborhood structures?**
→ **Yes**, if produced using an **injective aggregation function** at each layer.

**Can GNNs fail to distinguish different structures?**
→ **Yes** — when two different graph structures produce the **same** computational graph.

**Key examples of GNN failure cases:**
- **Mean and Max aggregators both fail** for certain graph pairs (nodes `v` and `v'` get the same embedding despite different neighborhoods)
- **Max fails** alone in other cases
- **Both Mean and Max fail** for symmetric structures

> **Reference: GIN (2019)** — Figure 3 shows examples of graph structures where mean and max aggregators fail to distinguish. Sum aggregation captures the full multiset; mean captures proportions/distributions; max reduces to a simple set (ignores multiplicities).

---

### Weisfeiler-Lehman (WL) Graph Isomorphism Test

The **graph isomorphism problem** asks whether two graphs are topologically identical. No polynomial-time algorithm is known yet.

The **Weisfeiler-Lehman (WL) test** (1968) is an effective and computationally efficient test that distinguishes a broad class of graphs.

**Goal:** Develop a GNN architecture that is provably the **most expressive** among all GNNs and is as powerful as the WL graph isomorphism test.

#### WL Color Refinement Algorithm:
1. Assign an **initial color** `c⁰(v)` to each node `v` (e.g., based on degree or node features)
2. Iteratively **refine** node color:
```
c^{k+1}(v) = HASH( c^k(v), { c^k(u) }_{u ∈ N(v)} )
```
where `HASH` maps different inputs to **different colors** (injective)

3. After `K` steps, `c^K(v)` **summarizes the structure of the K-hop neighborhood** of node `v`

**HASH table example (injective):**
| Input | Color |
|---|---|
| 1,1 | 2 |
| 1,11 | 3 |
| 1,111 | 4 |
| 1,1111 | 5 |

**Outcome:**
- If after K steps of refinement the color histograms of two graphs are **different** → graphs are **non-isomorphic**
- If they are the **same** → graphs may be isomorphic (the WL test can fail on some edge cases)

At depth `k/K=1`, structures may appear similar; at deeper depths, non-isomorphic graphs become distinguishable.

## Page 3 — Graph Isomorphism Network (GIN)

### Key Results from "How Powerful are Graph Neural Networks?" (Xu et al., ICLR 2019)

The landmark paper by Keyulu Xu, Weihua Hu, Jure Leskovec, and Stefanie Jegelka establishes:

1. GNNs are **at most** as powerful as the WL test in distinguishing graph structures
2. Conditions on the **neighbor aggregation** and **graph readout functions** under which a GNN is **as powerful as** the WL test are established
3. Graph structures that **cannot be distinguished** by popular GNN variants like **GCN** (Kipf & Welling, 2017) and **GraphSAGE** (Hamilton et al., 2017) are identified and characterized
4. A simple neural architecture — the **Graph Isomorphism Network (GIN)** — is developed, with discriminative/representational power equal to the WL test

---

### Important Theorem (Theorem 3)

> Let `A: G → ℝᵈ` be a GNN. With a sufficient number of GNN layers, `A` maps any graphs `G₁` and `G₂` that the WL isomorphism test decides as **non-isomorphic** to **different embeddings**, if the following conditions hold:

**(a)** `A` aggregates and updates node features iteratively with:
```
h_v^(k) = φ( h_v^(k-1), f( { h_u^(k-1) : u ∈ N(v) } ) )
```
where the functions `f` (operates on multisets) and `φ` are **injective**.

**(b)** `A`'s graph-level readout, which operates on the multiset of node features `{ h_v^(K), ∀v ∈ V }`, is **injective**.

**Expressiveness ranking of aggregators:**
```
Sum (most expressive) > Mean > Max (least expressive)
```
- **Sum** captures the full multiset (counts and types of neighbors)
- **Mean** captures the proportion/distribution of neighbor types
- **Max** reduces the multiset to a simple set — ignores multiplicities entirely

---

### GIN Update Rule

Since **Multi-Layer Perceptrons (MLPs) are universal function approximators**, GIN uses MLPs to model and learn both `f` and `φ` (the injective aggregation and combination functions).

**GIN message update rule:**
```
h_v^(k) = MLP^(k)( (1 + ε^(k)) · h_v^(k-1) + Σ_{u ∈ N(v)} h_u^(k-1) )
```
Where:
- `ε^(k)` = a learnable scalar (or fixed to 0) — controls how much the node's own embedding is weighted relative to the sum of neighbor embeddings
- The sum aggregation (`Σ`) ensures injectivity over multisets
- The MLP ensures the combination function `φ` is injective

> **GIN is a maximally expressive (powerful) GNN** among the class of GNNs — it matches the discriminative power of the WL graph isomorphism test.

---

### Expressive GNN Block Architecture

An expressive GNN block takes the following form:

```
[Pre-layers (MLPs)]
      ↓
[GNN Layer] → [GNN Layer] → ... → [GNN Layer]
      ↓
[Post-layers (MLPs)]
      ↓
[Predictions]
```

- **Pre-layers** (e.g., for node classification tasks): MLP layers applied to node features before message passing
- **GNN layers**: stacked GIN layers for deep message passing
- **Post-layers** (e.g., for graph classification tasks): MLP layers applied after aggregation, often with global pooling

## Key Takeaways

1. **Permutation invariance** is essential for GNNs: the same graph represented with different node orderings must yield the same output. This is achieved because each GCN layer is invariant to node permutations.

2. **Permutation equivariance** ensures that if nodes are reindexed, their embeddings are reindexed in the same way — critical for node-level and edge-level tasks. Graph-level tasks achieve full **invariance** via global pooling.

3. Unlike images and text, **graphs have no canonical node ordering** — permuting nodes doesn't change the graph's meaning, so GNNs must be designed to reflect this.

4. **Expressive power** measures a GNN's ability to map structurally different neighborhoods to **different embeddings** via injective aggregation. GNNs can fail when different graph structures produce the same computational graph (e.g., symmetric neighborhoods).

5. The **Weisfeiler-Lehman (WL) test** provides a theoretical upper bound on GNN expressiveness. It works by iteratively refining node "colors" based on their neighborhood multisets using an injective hash function.

6. **Aggregation method expressiveness ranking:** Sum > Mean > Max. Sum is the only aggregator that preserves the full multiset structure and is therefore maximally expressive.

7. **GIN (Xu et al., ICLR 2019)** is the theoretically most expressive GNN architecture, matching the WL test. Its update rule uses sum aggregation with a learnable `ε` parameter and MLP combination functions, both of which are injective.
