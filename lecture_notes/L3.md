## Page 1 — Overview: GCN Training and Testing (Inductive)

### Reminder from Lecture 2

A **generalized message propagation rule** updates node embeddings in a GCN layer via two steps:
1. **Aggregate** information from "myself" (a given node) and "my neighbors"
2. **Apply a linear transformation**

The generalized propagation rule is:
```
H_{k+1} = f(H_k, A)
```

Node embedding update rules (from DGL-2):

**a) Single node update:**
```
h_{k+1}^(n) = a[ β_k + Ω_k · h_k^(n) + Ω_k · agg[n,k] ]
```
*(self-encoding + neighborhood encoding)*

**b) Update for all nodes:**
```
H_{k+1} = a[ β_k 1ᵀ + Ω_k H_k + Ω_k H_k A ]
         = a[ β_k 1ᵀ + Ω_k H_k (A + I) ]
```

**Ultimate goal:** Use the learned embeddings in the final layer `H_K` for downstream learning tasks (regression/classification).

---

### Designing a GCN: Step-by-Step Training Process

| Step | Action |
|---|---|
| **1** | Define a neighborhood **aggregation function** (active research area) |
| **2** | Define the **building blocks** of a GCN layer: linear transformation, nonlinear activation |
| **3** | Define the **loss function**: binary/multiclass cross-entropy (CE) for classification; least squares/MSE for regression. For classification, output is passed through sigmoid or softmax before CE. |
| **4** | Define the **prediction head** (node, edge, or graph level), including hyperparameters β (bias) and ω (weights) |
| **5** | **Optimize** the loss over embeddings and hyperparameters using **Stochastic Gradient Descent (SGD)** |

**SGD Parameter Update Rule:**
```
Θ_t = Θ_{t-1} − η ∇ℒ(Θ_{t-1})
```
Where:
- `Θ` = all network parameters = `{W, β_k, Ω_1, ..., Ω_{K-1}}`
- `η` = learning rate (training walk)
- Forward pass → compute loss → backward pass (chain rule) → update parameters

---

### Loss Functions

**Node-level regression (multi-output):**
```
ℒ(Θ) = ||H_K W − Y||²_F = (1/C) Σ (H_K w_c − y_c)²
```
Where:
- `H_K ∈ ℝⁿˣᵈₖ` = K-th layer embeddings
- `W ∈ ℝᵈₖˣᶜ` = prediction head weights
- `Ŷ ∈ ℝⁿˣᶜ`, `Y ∈ ℝⁿˣᶜ` = predicted and ground-truth outputs

**Optimization objective:**
```
min_Θ ℒ(Θ) = ||Ŷ − Y||²_F
```

---

### Prediction Heads

**Node-level prediction head:**
```
ŷ^(n) = sig[ β_K + ω_K h_K^(n) ]
```
The classifier maps the K-th embedding of node `n` to a predicted output score.

**Edge/link prediction head:**
```
ŷ^(mn) = sig[ h_m^(K)ᵀ h_n^(K) ]
```
Predicts whether an edge exists between nodes `m` and `n` using the dot product of their embeddings.

---

### GCN Training Flow (Forward + Backward)

```
Input X = H_0
    ↓
GCN layers: H_1, H_2, ..., H_K
    ↓
Final layer H_K (embeddings)
    ↓
Prediction head (MLP / sigmoid / softmax)
    ↓
Loss ℒ(Θ)
    ↓
Backpropagation → SGD update
    ↓
Optimal Θ* = {Ω_1*, ..., Ω_{K-1}*, W*}
```

Loss optimization runs iteratively over training epochs until convergence. The embedding of each training node passes through all GCN layers and is updated with every gradient step.

---

### Inductive Testing: Predicting on Unseen Nodes

After training, to embed and predict for a **new/unseen testing node**:

1. **Connect** the testing node to other nodes (e.g., use dot product between original features to define edges)
2. **Forward pass** the original features through the GCN layers → get the final embedding of the testing node (**inductive node embedding**)
3. **Pass** through the final MLP prediction head
4. **Predicted output** is obtained
5. **Evaluate** using the real (ground-truth) output → MAE / MSE

> **Inductive capability** means GCNs can generalize to nodes (or entire graphs) not seen during training — one of their most powerful properties.

## Page 2 — Inductive Capability & Graph-Level Prediction

### Inductive Capability of GCNs

**Question:** What if the new node is NOT connected to existing nodes?

**Answer:** ✅ Yes, we can still predict! Because `Â = A + I`, the node is **self-connected** by default. The update becomes:
```
h_{k+1}^(n) = a[ β_k + Ω_k · h_k^(n) + 0 ]
```
The neighborhood encoding term is **zero**, and only the **self-encoding** component contributes. Prediction is still possible.

---

### Can GCNs Generalize to Many New Nodes?

✅ Yes — GCNs can generalize to:
- New individual nodes as they arrive
- Entirely new graphs with different sizes and topologies

**Why?** The key lies in **feature aggregation** and **parameter sharing** at the node level:
- All nodes share the **same** weight matrices `Ω_k` at each layer
- This dramatically reduces the number of parameters
- The network learns "what connections mean" globally, not per-position

**What happens without parameter sharing?**
- Separate parameters would be learned per node
- The network would need to relearn connection semantics at each position
- Training would require many graphs with the **same topology** → impractical

**Inductive generalization:**
```
G = (V, E, A, X)  →  G' = (V', E', A', X')
```
A trained GCN can process `G'` (with different size/structure) at test time.

---

### Graph-Level Prediction

**Problem:** How to extend node-level regression/classification to **graph-level** tasks?

**Hint:** Leverage integration — aggregate node embeddings across the entire graph, then apply the same supervised learner.

**Steps:**
1. Run GCN layers to get K-th node embeddings `H_K`
2. **Integrate/combine** node embeddings → graph embedding
3. Apply prediction head (MLP, sigmoid, etc.)

**Graph-level prediction dimensions:**
- `H_K ∈ ℝⁿˣᵈₖ` (node embeddings)
- `W ∈ ℝᵈₖˣᶜ` (prediction weights)
- `Ŷ ∈ ℝⁿˣᶜ`, `Y ∈ ℝⁿˣᶜ` (predicted and GT outputs)

---

### Graph-Level Prediction Head: Pooling Methods

#### 1. Global Mean Pooling
```
h_K^G = Mean{ h_K^(i) ∈ ℝᵈₖ, ∀i ∈ V_G }
```
Averages the final node embeddings across all nodes in the graph.

#### 2. Global Max Pooling
```
h_K^G = Max{ h_K^(i) ∈ ℝᵈₖ, ∀i ∈ V_G }
```
Takes the element-wise maximum across all node embeddings. Keeps the most activated (strongest) feature per dimension.

#### 3. Global Sum Pooling
```
h_K^G = Sum{ h_K^(i) ∈ ℝᵈₖ, ∀i ∈ V_G }
```
Sums all node embeddings — can collapse without normalization.

**⚠️ Limitation of Global Pooling:**
> Global pooling over a large graph will **lose information** and cannot differentiate between different graph structures.

**Counter-example:** Consider:
- `G1 = {-0.5, 1, -0.6, 0, 0.1}` → sum = 0
- `G2 = {18, 0, -5, -13}` → sum = 0

Both graphs have **different embedding distributions** but identical sum → indistinguishable by global sum pooling.

---

### Hierarchical Pooling: DiffPool (2018)

To overcome the limitations of flat global pooling, **DiffPool** (Ying et al., NeurIPS 2018) uses **hierarchical graph representation learning with differentiable pooling**:

- At each hierarchical level, run a GNN to get node embeddings
- Use those embeddings to **cluster nodes together**
- Run another GNN layer on the coarsened graph
- Repeat for L levels → final output representation used for classification

✅ This allows for **better graph differentiation**, as structure is progressively compressed while preserving local topology.

> **Reference:** Ying et al. "Hierarchical graph representation learning with differentiable pooling." NeurIPS 2018.

## Page 3 — GNN Layer Operations (Building Blocks)

### Overview of GNN Layer Operations

A GNN layer is composed of the following **building blocks**, which can be reordered, merged, or removed depending on the task:

| Operation | Purpose |
|---|---|
| **AGG** (Aggregation) | Integrate information from self & neighbors — the GNN hallmark |
| **Transform** | Linearly transform embeddings to represent them better — classical in ML |
| **MSG Passing** | The mixed actions of AGG + Transform: `H_{k+1} = f(H_k, A)` |
| **Nonlinearity** | Capture complexity and identify important patterns (e.g., ReLU) |
| **BN** (Batch Normalization) | Stabilize optimization & control embedding variance between layers |
| **Dropout** | Drop nodes/edges to regularize and increase expressiveness |
| **Prediction Head** | Define the target learning task and its parameters |

**Important notes:**
1. The **order** of operations can change depending on the task rationale
2. Some operations can be **merged or removed**
3. A critical design question: *first aggregate then transform, or first transform then aggregate?*

## Page 4 — Aggregation Methods in Detail

### Local Aggregation at the Node Level

#### Mean Aggregation
Standard mean aggregation for a node `n`:
```
agg[n] = (1/|ne[n]|) Σ_{m ∈ ne[n]} h_m
```
*(averaging the embeddings of neighbors)*

The full GCN layer update becomes:
```
H_{k+1} = a[ β_k 1ᵀ + Ω_k H_k (AD⁻¹ + I) ]
```

#### Kipf Normalization (Symmetric)
**Logic:** Information from nodes with many neighbors should be **downweighted** — high-degree nodes contribute less unique information per connection.

Kipf-normalized aggregation:
```
agg[n] = Σ_{m ∈ ne[n]} h_m / √|ne[n]| √|ne[m]|
```

The full GCN layer update:
```
H_{k+1} = a[ β_k 1ᵀ + Ω_k H_k (D⁻¹/² A D⁻¹/² + I) ]
```
This symmetric normalization balances the degree of both source and target nodes.

#### Max Pooling
Max-pooling aggregates by taking the **element-wise maximum** across neighbor embeddings:
```
agg[n] = max_{m ∈ ne[n]} [ h_m ]
```
Returns the strongest activation per embedding dimension across all neighbors of node `n`.

---

### Aggregation by Attention (Graph Attention Networks)

**Key motivation:** Previous aggregation methods consider neighbors **equally** or weight them by graph topology (degree). Attention allows weighting based on **learned node embedding similarity**.

**Rule: first transform, then pay attention.**

**Step 1 — Linearly transform embeddings:**
```
H'_k = β_k 1ᵀ + Ω_k H_k
```
*(produces transformed embeddings)*

**Step 2 — Define a node-to-node similarity (attention) matrix:**
```
S_{mn} = φ_k^T [ h'_m ; h'_n ]
```
Where `[h'_m ; h'_n]` is the concatenation of transformed embeddings of nodes `m` and `n`, and `φ_k` is a learned attention vector.

**Step 3 — Normalize using Softmax (masked by adjacency):**

Attention weights are **normalized** to be positive and sum to one via the softmax operation, but **masked** by the adjacency matrix so that each node only attends to **itself and its neighbors**:
```
H_{k+1} = a[ H'_k · Softmax(S, A + I) ]
```

The function `Softmask[•, •]` applies softmax separately to each column, setting values where the second argument is zero to **−∞**, ensuring attention to non-neighboring nodes is **zero**.

**Graph Attention Network (GAT) combines:**
- Weights computed from the **data** (node embeddings) — like self-attention
- Weights constrained by the **adjacency matrix** (graph topology) — like GCN

This gives the model the expressive power of attention while respecting the graph structure.

## Key Takeaways

1. **GCN training** follows 5 structured steps: define aggregation → define layer operations → define loss → define prediction head → optimize with SGD/backpropagation.

2. The **inductive capability** of GCNs is one of their most powerful features — they can generalize to unseen nodes and entirely new graphs through parameter sharing and feature aggregation.

3. **Without parameter sharing**, GCNs would need to relearn connection semantics at each node position and require many graphs with the same topology — making the approach impractical.

4. **Graph-level prediction** is achieved by integrating (pooling) node embeddings into a single graph-level vector. Simple global pooling (mean/max/sum) can lose structural information.

5. **Hierarchical pooling (DiffPool)** addresses this limitation by progressively clustering and coarsening the graph across multiple levels.

6. A GNN layer is composed of modular **building blocks**: AGG, Transform, MSG Passing, Nonlinearity, Batch Normalization, Dropout, and Prediction Head — which can be reordered or combined.

7. **Aggregation methods** range from simple summation and mean (treating neighbors equally), to Kipf normalization (downweighting high-degree nodes), to max pooling (strongest activation), to **attention-based** aggregation (Graph Attention Networks), which learns to weight neighbors based on embedding similarity while masking non-neighbors.
