## Page 1 — Generative Learning Tasks Formalization

### Two Fundamental GNN Aims

GNNs serve two distinct high-level purposes:

1. **Predict and analyze patterns on given graphs** — e.g., predict the label of a node or a graph (discriminative/supervised)
2. **Learn the distribution of given graphs and generate novel graphs** — e.g., generate target graph B from source graph A (generative)

The generative paradigm involves learning a **source graph distribution** and mapping it to a **target graph distribution**.

---

### Supervised Generative GNN Tasks (Generic Formulation)

In the generic supervised generative task, the input and output are both graphs with potentially different sizes and features:

**Input (source domain A):**
- Adjacency matrix `A` (n × n nodes)
- Node feature matrix `X` (n × n nodes)
- Edge feature tensor `E` (n nodes × n nodes × edge features)

**Output (target domain B):**
- Adjacency matrix `A'` (n' × n' nodes)
- Node feature matrix `X'` (n' nodes)
- Edge feature tensor `E'` (n' nodes × n' nodes)

**Key equations:**
```
f_GNN(A, X, E) = (Ã', X̃', Ẽ')     (mapping function)
GT ⇒ A', X', E'                      (ground truth)
```

**How to define the loss function?**
This depends on **what we want to generate** (only A, A and X, or A + X + E). We always need both `A` and `X = H₀` matrices in the GCN node embedding rule.

---

### Three Cases of Generative Tasks

#### Case 1: Target Graph Has No Node/Edge Features

**Aim:** Generate only the graph **adjacency matrix**.

**GNN mapping function:**
```
f(A, X) = (Ã', X̃')     using GCNs
```
Where `σ(h_i, h_j)` produces the target A' matrix (e.g., dot product of node embeddings).

**How to initialize `X = H₀`** when there is no input feature matrix?
1. **Randomly** — sample from a distribution
2. Using **topological attributes** of each node (e.g., degree, centrality)
3. Using an **identity vector** of `[1, 1, ..., 1]`

**GNN loss function:**
```
ℒ₁ = dist(A', Â')
```
Only the adjacency matrix is optimized — no need to optimize over X'.

#### Case 2: Target Graph Has Only Node Features

**Aim:** Generate both the **graph adjacency matrix and node feature matrix**.

**GNN mapping function:**
```
f(A, X) = (Ã', X̃')
```

**GNN loss function:**
```
ℒ₂ = dist(A', Â') + λ · dist(X', X̃')
```
A weighted combination of topology loss and node feature loss, where `λ` controls the balance (L₂ / sparsity regularizer).

#### Case 3: Target Graph Has Both Node AND Edge Features

**Aim:** Generate the adjacency matrix, node feature matrix, **and edge feature matrices**.

**GNN mapping function:**
```
f(A, X, E) = (Ã', X̃', Ẽ')
```

**GNN loss function:**
```
ℒ₃ = dist(A', Â') + λ₁ · dist(X', X̃') + λ₂ · dist(E', Ẽ')
      ↑ topology    ↑ node features        ↑ edge features (key objective)
```
Note the scale differences: O(100) terms for node features vs. O(1) for edges — balance terms carefully.

### Various Supervised (Conditional) Generative GNN Tasks

Based on Bessadok et al. (2022), generative GNN tasks span multiple dimensions:

**Generative GNN dimensions:**
- **Domain axis:** Source and target graphs can be in different domains (e.g., different modalities)
- **Resolution axis:** Source and target graphs can have different resolutions
- **Time axis:** Target graphs can represent future states (dynamic/temporal prediction)

**Task types include:**
- **Single graph prediction:** One source graph → one target graph
- **Multigraph prediction:** One source → multiple target graphs (e.g., different morphological networks from the same subject)
- **Graph super-resolution:** Low-resolution graph → super-resolved high-resolution graph
- **Brain graph evolution prediction:** Brain graph at time t → predict brain graph trajectory at t+1, t+2, ..., t+k (time-dependent GNN, dynamic graph generation/forecasting)

## Page 2 — Self-Supervised/Unsupervised Graph Generation & Taxonomy

### Self-Supervised / Unsupervised Generative GNN Tasks

In the supervised case, a ground-truth target graph exists. In the **self-supervised / unsupervised** setting, there is no corresponding GT graph — the goal is to generate graphs from a learned distribution (clustering-based: no longer corresponding GT given).

**Graph Encoders:** Graph → Embeddings (encode a given graph `g` into embeddings `H_G`)
**Graph Decoders:** Embeddings → Graphs (generative power — given an embedding `H_G` → decode to graph `g̃`)

**Utility of graph generation:**
- Understand the **graph formation process**
- Identify **abnormal** parts of a graph
- **Predict** new structures
- **Simulate** novel graph structures
- **Graph completion** when only partial graph data is available

**Real-world examples:**
- Generate a new **molecule** that cures a disease (given a class of toxic/non-toxic molecules, generate new molecules satisfying the class)
- Generate the **dynamic evolution of brain connectivity graphs** to spot atypical alterations linked to neurological disorders

### ML Basics for Self-Supervised/Unsupervised Graph Generation

**Goal:** Given graphs sampled from `p_data(g)`, we aim to:
1. **[Density estimation]** Learn a good model: `p_model(g; θ) ~ p_data(g)`
2. **[Sampling]** Identify how to sample from `p_model(g; θ*)` to generate a new graph

**Key distinction:**
- `p_data(g)` = the **true data distribution** — never known to us, only observed through existing graph samples
- `p_model(g; θ)` = the **model**, parameterized by `θ`, that approximates `p_data(g)`

#### Step 1: Density Estimation

Use **maximum likelihood estimation** to make `p_model(g; θ) ~ p_data(g)`:
```
θ* = arg max_θ E_{g ~ p_data} [ log p_model(g; θ) ]
   = arg min_θ -E       (minimize negative log-likelihood)
```
Find `θ*` such that for observed graph points `gᵢ ~ p_data`, the sum `Σᵢ log p_model(gᵢ; θ*)` has the highest value among all choices of `θ`.

→ Find the model that is **most likely to have generated the observed graphs** `g`.

#### Step 2: Sampling

Sample from the complex distribution `p_model(g; θ*)`. The most common approach:

1. **Sample from a simple noise distribution:**
```
zᵢ ~ N(0, 1)     (Gaussian noise)
```

2. **Transform the noise** via a deep network function `f_θ(·)` trained on input graphs:
```
g̃ᵢ = f(zᵢ; θ*)     (newly generated graphs)
```

This is the basis of **VAE-style** and **GAN-style** graph generation.

### Taxonomy of Deep Graph Generation (Guo et al., 2023)

The taxonomy organizes graph generation methods along two major branches:

#### Unconditional Generation
Generates graphs **without** any conditioning input (does not always imply a fully unsupervised framework).

**One-shot generating** — generates the entire graph at once:
- **Adjacency-matrix-based:** Message-passing-based, MLP-based, Transposed-convolution-based
- **Edge-list-based:** Random-walk-based, Node-similarity-based

**Sequential generating** — builds the graph step by step:
- **(a) Node-sequence-based:** Adds nodes one at a time, then connects them
  - `(v₁, {}) → (v₂, {e₁₂}) → (v₃, {e₁₃, e₂₃}) → (v₄, {e₃₄, e₂₄})` → adjacency vector
- **(b) Edge-sequence-based:** Adds one edge at a time (with associated nodes)
  - `(e₁₂, {v₁, v₂}) → (e₁₃, {v₁, v₃}) → (e₁₄, {v₁, v₄}) → (e₂₃, {v₂, v₃})` → connect existing nodes
- **(c) Motif-sequence-based:** Adds recurring structural motifs (subgraph patterns) step by step
  - `C₁ → C₂ → C₃ → C₄` (motif clusters)
- **(d) Rule-sequence-based:** Applies domain-specific rules sequentially (e.g., for molecules):
  - add branched atom → construct ring → make atom 'C' → add single bonds

#### Conditional Generation
Generates graphs **conditioned on** some input context:

- **Conditioning on sequence:** Node-sequence, Edge-sequence, Motif-sequence, Rule-sequence
- **Conditioning on semantic context:** Independency-based, Dependency-based, Domain-agnostic-based, Domain-specific-based
- **Conditioning on graph:** Node-edge co-transformation (Editing-based, Embedding-based)

## Page 3 — Unsupervised & Supervised Generative GNN Models

### Unsupervised Generative GNN Tasks — Self-Generation

#### GraphVAE (Simonovsky et al., ICANN 2018)

**"GraphVAE: Towards Generation of Small Graphs Using Variational Autoencoders"**

**Setup:** Let `G = (A, E, F)` be a graph with adjacency matrix `A`, edge attribute tensor `E`, and node attribute matrix `F`. The goal is to **learn an encoder and decoder** to map between the space of graphs `G` and their continuous embeddings `z`.

**Architecture:**
- **Encoder:** GNN (graph convolutional encoder) that encodes the input graph `G` into a continuous latent representation `z`
- **Decoder:** A **deterministic** simple MLP with three outputs in its last layer:
  - Sigmoid activation to compute `Ã` (adjacency)
  - Edge-wise softmax to compute `Ẽ` (edge attributes)
  - Node-wise softmax to compute `F̃` (node features)
  - At test time: take edge and node-wise argmax → discrete graph on ≤ k nodes

**Probabilistic (VAE) setting:**
```
Encoder: q_φ(z|G) ~ N(μ, σ²I)    (variational posterior)
Decoder: p_θ(G|z)                  (generative distribution)
Prior: p(z) ~ N(0, I)
```

**Loss objective of Variational Autoencoders:**
```
ℒ(θ, φ; G) = E_{q_φ(z|G)}[log p_θ(G|z)] − KL[q_φ(z|G) || p(z)]
```
- **First term (reconstruction loss):** Enforces high similarity of sampled/generated graphs to the input graph `G`
- **Second term (KL divergence):** Regularizes the code space to allow sampling of `z` directly from `p(z) = N(0, I)` instead of `q_φ(z|G)`. The decoder is loosely trained to learn a **high-level compression** of the input rather than merely copying it.

The process can be **conditioned on a label** for controlled sampling at test time.
Graph matching (using max-pooling graph matching) is used to align sampled and input graphs.

#### Message-Passing-Based One-Shot Generation

An alternative one-shot approach using message passing:
```
Z ~ N(1, 0)     (unit matrix initialization: Z of noise)
A⁰ → GCN msg → h₁⁰, h₂⁰ ... → Node update + Edge update → p_data ~ p(g; θ)
```
At each iteration, both node and edge updates are performed until convergence.

#### The Universal Generative Power

Trained decoders transform sampled noise directly into real graphs:
```
zᵢ ~ N(0, 1)  →  f_model(zᵢ; θ*)  →  generated graphs
```
The model learns independently of the actual generation task, and decodes noise into valid graph structures that approximate `p_data`.

### Supervised Generative GNN Tasks — Conditional Generation

#### Conditioning on Graphs: Embedding-based vs. Editing-based

**Embedding-based NECF (Node-Edge Co-generation Framework):**
- **Encoder:** Embeds the input graph `G_s` into a latent representation
- **Decoder:** Generates an output graph `G_t` conditioned on this embedding, first determining the number of nodes `N'`, then generating `N'` nodes sequentially. At each step, edges from existing nodes to the new node are determined, as well as node features.

**Editing-based NECF:**
- Produces target graph `G_t` by **editing** the source graph `G_s` through a sequence of add/remove edge actions
- An action-step MLP decides: add edge? remove edge? which node to connect?

#### DAG-to-DAG Translation (Kaluza et al., NeurIPS Workshop 2018)

A neural framework for **Directed Acyclic Graph (DAG) to DAG translation**:
- Input: DAG `G_s`; Output: DAG `G_t`
- Used for tasks like program synthesis, computational graph optimization
- The DAG structure enables clean topological ordering for sequential generation

### Encoder-Decoder GNN Case Study: Graph UNet (Gao et al., ICML 2019)

**"Graph U-Nets"** — extends the U-Net architecture from image segmentation to graphs.

**Architecture overview:**
- An encoder-decoder structure with **skip connections** (self-reconstruction)
- Each block consists of a **gPool layer** (graph pooling) and a **GCN layer**
- The decoder uses a **gUnpool layer** (graph unpooling) and a GCN layer

**Proposed Graph Pooling (gPool):**

Step 1 — Compute projection scores:
```
y = X · (||p||) ∈ ℝⁿ     (scalar projection for each node using learned vector p)
```

Step 2 — Select top-k nodes:
```
idx = rank(y, k)           (indices of top-k scoring nodes)
ỹ = sigmoid(y(idx))        (gating values for selected nodes)
```

Step 3 — Extract subgraph:
```
X̃ = X(idx, :)              (features of selected nodes)
Ã^{l+1} = A(idx, idx)      (subgraph adjacency)
X^{l+1} = X̃ ⊙ (ỹ 1_d^T)   (gated node features)
```
- Uses the indices to form a new graph → creates **projected feature map** `X̃` and new adjacency `Ã^{l+1}`
- The graph pooling layer output: `A^{l+1}` and `X^{l+1}`

**Proposed Graph Unpooling (gUnpool):**
- The corresponding unpooling operation reverses pooling by **distributing** features back to the original node positions using stored indices
- Uses skip connections from the encoder to fuse low-level spatial features with decoder outputs
- The output features of nodes in the last layer are **network/node embeddings** usable for classification, link prediction, etc.

**Self-reconstruction loss:**
```
||G − G̃||²   (reconstructed graph should match input)
```

## Page 4 — Graph UNet Extensions & Evaluation Measures

### Graph UNet for Graph Super-Resolution: GSR-Net (Isallari et al., 2018)

**Application:** Super-resolve brain graphs — generate high-resolution (HR) brain graphs from low-resolution (LR) inputs.

**Architecture — Graph U-Autoencoder Block:**
```
Inputs → [Graph Pooling Layer] → GCN → GCN → [Graph Unpooling Layer] → Generated HR brain graphs
                ↕                                        ↕
          (encode to lower res)                  (decode to higher res)
                    └──────── self-reconstruction loss ────────┘
```
- The encoder compresses graph structure via pooling
- The decoder reconstructs/super-resolves via unpooling
- An additional block can be added for super-resolution

**Open question explored:** How to generalize Graph UNet to a target with **edge attributes**?

### NED-VAE (Guo et al., 2020)

**"Interpretable Deep Graph Generation with Node-Edge Co-Disentanglement"**

Addresses graph generation with both node AND edge attributes via disentangled VAE:
- **Node Encoder / Graph Encoder / Edge Encoder** produce separate latent representations `z_F`, `z_G`, `z_E`
- Each encoder learns `p(z | data)` independently
- **Node Decoder / Graph Decoder / Edge Decoder** reconstruct `G(E, F)` from disentangled latents
- Losses: target sample SSL `||G − G̃||²` + source sample SSL `||G_s − G̃_s||²` + total loss `f_{mc}(·)`
- Latent spaces:
  ```
  z_F ~ N(μ_F, σ_F)
  z_G → PB (graph-level)
  z_E ~ (edge latent)
  ```

### Evaluation Measures for Graph Generation

The evaluation strategy depends on whether a ground-truth target graph is available.

#### When Ground-Truth Is Available (Supervised Setting)

**1. Element-wise distance (MAE):**
```
MAE(A_i, Ã_i) = ||A_i − Ã_i|| ≈ 0.01
```
Measures direct element-wise difference between predicted and GT adjacency matrices.

**2. Topological measures (graph topology soundness):**
```
MAE(eigenvector centrality), degree, etc.
```
Captures how well the **graph topology** is preserved (using graph-theoretic metrics like centrality, degree distribution).

#### When Ground-Truth Is Unavailable (Self/Unsupervised Setting)

Since we have no direct GT, we compare the **distribution** of generated graphs to the training graph distribution:

**General metrics:**
- **Statistics-based:** Average KLD (KL Divergence between distributions), MMD (Maximum Mean Discrepancy)
- **Classifier-based:** Accuracy-based, FID-based (Fréchet Inception Distance between multivariate Gaussian distributions)
- **Intrinsic-quality-based:** Validity, Uniqueness, Novelty

**Condition-specialized metrics:**
- **Graph-property-based:** Mapping-relationship-based measures

**Key metrics defined:**
```
KLD: KL Divergence between distributions
MMD: Maximum Mean Discrepancy
FID: Fréchet Inception Distance between multivariate Gaussian distributions
```

**Key reference:** Thompson et al. (ICLR 2022) — "On Evaluation Metrics for Graph Generative Models" — argues that standard image metrics are not always appropriate for graph generative models. Proposes neural network-based metrics using graph embeddings extracted from an untrained GNN, recommending two metrics for computational efficiency.

## Key Takeaways

1. **Generative GNNs** extend beyond discriminative tasks (predict node/graph labels) to **generating new graphs** from learned distributions — opening up drug discovery, brain connectivity modeling, and molecular simulation.

2. **Three supervised generative task levels** depend on what components of the target graph need to be generated: (1) adjacency only → ℒ₁, (2) adjacency + node features → ℒ₂, (3) adjacency + node + edge features → ℒ₃, each adding weighted distance terms.

3. **Unsupervised graph generation** is formalized as a two-step problem: **density estimation** (learn `p_model ~ p_data` via maximum likelihood) and **sampling** (transform Gaussian noise through a trained decoder to produce new graphs).

4. **Sequential generation strategies** include node-sequence (add nodes then edges), edge-sequence (add edges with nodes), motif-sequence (add recurring subgraph patterns), and rule-sequence (apply domain-specific chemical/structural rules).

5. **GraphVAE** uses a GNN encoder + MLP decoder in a VAE framework, with a reconstruction loss + KL divergence loss. The KL term regularizes the latent space to be Gaussian, enabling pure noise-to-graph sampling at test time.

6. **Graph UNet** adapts the encoder-decoder U-Net architecture to graphs using learnable **gPool** (top-k node selection via projection scores) and **gUnpool** (index-based feature redistribution) operations with skip connections for self-reconstruction.

7. **Evaluation of generative GNNs** differs based on whether GT exists: supervised settings use direct MAE/topology metrics; unsupervised settings require distribution-level metrics (KLD, MMD, FID) measuring whether generated graphs statistically match training data.
